# 内容规范

## 1. 文件名

`姓名-岗位-电话号码.docx`（PDF同名）。例：`张三-B端销售-13800138000.docx`。

## 2. 求职意向写法

- 格式：`求职意向：岗位大类（方向）`
- 岗位用**大类通用名**：销售、B端销售、AI产品经理、AI应用开发、AI大模型开发、FDE、数据分析等。
- 括号里补充方向：`销售（AI方向）`、`B端销售（SaaS方向）`。
- **禁止**：写具体公司名（"字节跳动""抖音本地生活"）、写现住地、写"应届/无经验"。

## 3. 模块顺序（按岗位）

| 岗位 | 顺序 |
|---|---|
| 销售/BD | 专业技能 → 比赛经历 → 项目经历 → 其他经历 → 证书 → 作品链接 → 自我评价（教育入页首） |
| AI产品经理 | 教育背景 → 项目经历 → 比赛经历 → 专业技能 → 证书与作品集 → 自我评价 |
| AI应用开发 | 教育背景 → 专业技能 → 项目经历 → 比赛经历 → 证书与作品集 → 自我评价 |
| 通用 | 教育背景 → 专业技能 → 项目经历 → 比赛经历 → 证书与作品集 → 自我评价 |

## 4. 各模块写法

### 专业技能
- 销售方向：3条左右——硬技能（工具/技术栈）、软技能（沟通/路演/抗压）、其他（自学/跨学科）。
- 技术方向：按技术栈分组，诚实标注深度（"可读写""基础开发"），不写"精通"。
- 不要写"我外向""我善于沟通"这种自我评价式句子，用具体技能词。

### 比赛经历（S/T/A/R）
- 标题行：比赛名（主办方） + 奖项标签 + 右侧日期。
- 四条：S背景、T任务、A行动、R结果，每条一行。
- A行动用 → 连接动作链。
- 奖项如实写，不夸大。

### 项目经历（S/A/R）
- 标题行：项目名 · 角色 + 右侧时间。
- S背景：发现什么痛点。
- A行动：做了什么（用 → 连接流程）。
- R结果：上线了吗、用户反馈、获奖/认可。
- 结尾附：线上体验链接 + GitHub链接。

### 其他经历
- 无bullet点，加粗前缀+正文。
- 每条一行，体现：自媒体运营、行业活动参与、社区贡献等。

### 证书
- 一行列完，不展开。

### 自我评价
- 3-4句，落到岗位。
- **不要重复前面模块已经写过的内容**。
- **不要直说性格**（"我外向""我喜欢研究人"），让HR从经历里自己体会。
- 结尾落到"愿意从一线做起，用结果证明自己"这类岗位导向。

## 5. 为什么不能写（注意事项）

1. **通用版原则**：投多家的简历，禁止出现只针对单一公司/岗位定制的词。否则投递别家会被看出是海投。
2. **奖项如实**：人气奖就是人气奖，不写成一等奖/冠军/金奖。
3. **不编造**：不虚构公司、实习、数字、项目；链接必须真实可访问。
4. **照片必放**：一寸证件照是硬要求。
5. **二维码必放**：有线上简历就放，是差异化记忆点。
6. **一页优先**：销售版必须1页。
7. **文案不要自己发挥**：用户给了参考文案就照抄；不要替用户"优化"成更华丽的表达。
